\label{sec:method}

\sys has six modules (\cref{fig:overview}), described in data-flow order:
corpus construction, extraction, verification, hierarchy, maintenance and
retrieval.

\subsection{Definitions-First Corpus Construction}
\label{sec:method:corpus}

We do not give the model whole statutes: a regulation such as \src{MiCA}
defines its vocabulary in a few articles and spends the rest on obligations
that refer back to them, so we take the definitions articles, glossaries,
classification conditions and business-model descriptions and nothing else. \Cref{tab:corpus} lists the result: 21 legal
instruments from the EU, the UK, the US and six international bodies, two
academic taxonomies~\cite{tasca2019taxonomy,zhang2026cryptotaxonomy} and the
DLT-Corpus paper~\cite{hernandez2026dltcorpus}, with reference lists and
large tables removed.

Each PDF is converted to text and cut by line ranges or regular-expression
markers specified once per document; US bills need the layout-preserving mode,
page footers are dropped, and the Senate print of the \src{CLARITY Act}, which
reproduces the House text, contributes only the substitute's definitions and
its network-token section. The corpus is one XML-tagged text file in which every document carries an
integer index and metadata and is split into \texttt{<section label="...">}
blocks, so a citation can name a document and a section unambiguously. The file
holds 32 sections and 97.8 thousand words, which the model's tokeniser counts
as 235,298 tokens.

\subsection{The Extraction Task (Task A)}
\label{sec:method:task}


The prompts are given verbatim in \cref{app:prompts}. The system instructions
define the objects of \cref{sec:problem} in the model's terms and state the grounding and quality
rules; they precede the corpus and never change, so the cache survives every
task. The user prompt states the scope (assets, DLT systems, actors, activities,
obligations or risks), gives the JSON schema, asks for ordering by category
and grounding count, and declares the corpus the only source of truth.

\textbf{Manifest.} Our first run cited section labels from memory and got
them wrong in 9\% of citations, with 65 term types. We therefore append a
\emph{manifest}: one line per document listing its index, title and every
exact section label, with the instruction that no other labels exist. The
manifest is generated from the corpus at run time, so it cannot drift from the
file the model sees.

\subsection{One Call over a Cached Corpus}
\label{sec:method:run}

We place the whole corpus in the system prompt, after the stable instructions
and behind a prompt-cache breakpoint~\cite{gim2024promptcache} with a one-hour lifetime; the task prompt
is the user message. Every later call pays only for the uncached part. The choice is also methodological:
recognising that \src{MiCA}'s ``referencing the value of one official
currency'' and the \src{GENIUS Act}'s ``fixed amount of monetary value'' answer
the same question needs both passages in view, which a retriever would have to
anticipate. The cost of a run is therefore linear in the
corpus size, with the corpus priced at the cache-read rate and only the task
prompt and the output priced in full; we report measurements in
\cref{sec:exp:rq1,sec:exp:rq2}.

A single streamed call produces the output. We disable adaptive thinking, which on
a first attempt spent more than 100,000 tokens without emitting text. We parse the JSON and, if a response is cut off by the output limit,
salvage every complete term type and flag the result as truncated.

\subsection{Citation Verification}
\label{sec:method:verify}

A quote may be invented, compressed or attached to the wrong section, so we
check all of them. For each citation we
look up the document and section, normalise both the quote and the section text
to lower-case alphanumerics, and accept the quote if it is a substring. If it is
not, we split the quote into 12-character shingles and accept it when at least
80\% of them occur inside one window of the section twice the quote's length.
The window tolerates footnote markers and PDF spacing and rejects a paraphrase
stitched from distant phrases. When a quote fails under the cited label but
passes under another label of the same document, we \emph{relabel} it,
correcting the section, keeping the model's label alongside, and counting the
citation as verified. Everything else is rejected; every citation carries a
verified flag, and the rejection rate measures desideratum~(D1). Verification establishes that the quote exists where the
model says it does; it does not establish that the quote supports the
dimension, a limit we return to in \cref{sec:exp:rq1}.

\subsection{From Term Types to a Hierarchy (Task B)}
\label{sec:method:hierarchy}

\textbf{One question per node.} With the catalogue $\mathcal{Y}$ in hand, Task~B
asks the model, for each term type $x$, how probable it is that $x$ is-a $y$
for every other term type $y$ in the same category, plus \emph{none}, meaning
$x$ is a top-level dimension. The prompt is given verbatim in
\cref{fig:prompttaskb}. One user message per $x$ carries the definition of
is-a from \cref{sec:problem}, the full record of $x$ and the candidate parents
by identifier, name and question. The model returns at most six entries, each
with a probability, a rationale of at most thirty words, and citations in the
format of Task~A; the top entry, unless it is \emph{none}, must cite at least
one passage. The corpus and a second cached block holding the compact
catalogue are read from cache, so each call sends only the record of $x$ and
its candidates.

\textbf{Normalisation.} We drop parents that are not in the candidate set, merge
duplicates, remove the \emph{none} entry while keeping its mass as $p_{\text{none}}(x)$
for reference, and renormalise the remaining weights to sum to one. Citations
are verified exactly as in \cref{sec:method:verify}.

\textbf{Consolidation into a DAG.} Every weighted edge is a candidate. We take
edges in decreasing weight and keep each one unless the parent already descends
from the child, which would close a cycle; a mutual pair $x \to y$, $y \to x$
thus resolves to the stronger direction, and an exact tie resolves by identifier
order and is reported. No weight threshold is applied; a display threshold
can hide weak edges later. The first kept edge of a node is its primary parent,
which gives a tree view.

\subsection{The DAG as a Label Space and Its Maintenance}
\label{sec:method:maintain}

Part~2 treats $G$ as the label space for Web content and runs the same loop
over every batch: sample, tag (Task~C), measure and discover (Task~E), and
evolve. Catalogue version $t$ is in force for one iteration; version 0 is the
DAG of Part~1 and is never modified, later versions only add to it, and every
node, edge and value added after the seed carries a \emph{candidate} status
with the iteration that produced it, so seed and discovered structure stay
distinguishable. Batches are disjoint, the sampler excluding every item drawn
before; an item is a title and abstract (for a patent, its abstract section)
capped at 450 words, kept when it is in English and its title or abstract
matches a fixed list of DLT terms (\cref{sec:exp:setup}).

\textbf{Tagging (Task C).} The model receives one cached system block, the
\emph{catalogue}: every term type with its identifier, question, values as
codes $v_1, v_2, \dots$ with their definitions, and its is-a parents with weights,
listed as the term types it refines. The Part~1 corpus is not sent, so a
request is the cached catalogue plus the item. The instructions
(\cref{app:prompts}) state what a tag asserts, that the text is about,
describes or clearly exhibits the category, and that a word used in passing
is not a tag; that several values of one term type may apply; that the most
specific applicable term type is preferred and ancestors are not repeated
unless they carry a value of their own; and that the model may propose, under
a separate key and only when confident, at most three values or term types the
catalogue lacks. For each item it returns tags $(y, v, \kappa, e)$, a term type, a value code, a confidence in $[0,1]$, and an evidence span of at most twenty
words copied from the item, plus the proposals and an off-topic flag. We
reject a tag whose term type is not in the catalogue; a value given as a code
or a label is resolved to a catalogue value exactly, then by string similarity
at ratio 0.85, and rejected otherwise; the confidence is clipped to $[0,1]$;
every evidence span is checked against the title and text with the matcher of
\cref{sec:method:verify}, and the result is recorded on the tag, which is kept
either way and reported as verified or not. We record the is-a ancestors of
each tagged term type, under every edge of $G$, as the item's implied term
types. The first item of a batch is tagged alone to write the cache, the rest
with 6 to 24 requests in flight at effort \texttt{medium}; a response that is
not valid JSON counts as an item with no tags. Proposals are grouped by the
term type they target and become seeds for discovery.

\textbf{Metrics for maintenance.} The consolidated DAG of
\cref{sec:method:hierarchy} is the label space that Part~2 maintains, so we
attach to it three measures of how well it discriminates: how many bits a walk down the DAG resolves, how early that walk
ends, and how many distinct leaves it reaches. All three are defined through
one random walk that uses the DAG as a classifier would, and we illustrate
each on the five-edge DAG of \cref{fig:toydag}, small enough to compute by
hand.

At a node $y$ with children $\mathrm{ch}(y)$ the kept edge weights define a
branching distribution
\begin{equation}
  q_y(x) = \frac{w(x \to y)}{\sum_{x' \in \mathrm{ch}(y)} w(x' \to y)}, \qquad x \in \mathrm{ch}(y),
  \label{eq:branch}
\end{equation}
the probability of stepping from $y$ to child $x$, so that heavy edges attract
more of the walk. In the example the weights at each node already sum to one;
in general they do not, since $w(x \to y)$ is the probability of $y$ as a
parent of $x$, not a share of $y$. A \emph{random descent} starts at a
uniformly chosen root, draws a child from $q_y$ at every node it visits, and
ends when it reaches a leaf. The walk is a device rather than a step of the
pipeline: it turns a static graph into a distribution over paths, so that
entropy applies. In the example every walk starts at the single root, steps to
proof of work with probability $0.5$, to proof of stake with $0.4$, or to
proof of authority with $0.1$, and from proof of stake continues to delegated
PoS with $0.9$ or to liquid staking with $0.1$.

\emph{Information gain} is the yield of the walk. At $y$ it is the entropy
$\entropy(q_y) = -\sum_x q_y(x) \log_2 q_y(x)$ in bits, the uncertainty the
choice at $y$ resolves: two equally weighted children resolve one bit, four
resolve two, and four children of which one carries almost all the weight
resolve close to zero, since the walk nearly always goes the same way; leaves
and single-child nodes resolve nothing. In the example the root resolves
$1.36$ bits, a little short of the $1.58$ that three equal children would
give, and proof of stake resolves $0.47$, since nine walks in ten take the
same edge. We report two aggregates. The \emph{sum over nodes}, $1.83$ bits in
the example, is the total discrimination the DAG holds. The \emph{expectation
along a descent} weights each node by how often a walk visits it: every walk
passes the root and collects its $1.36$ bits, but only $40\%$ reach proof of
stake and collect the further $0.47$, so a walk resolves $1.36 + 0.4 \times
0.47 = 1.55$ bits. The expectation is the fairer figure and the one we quote
as \emph{bits per descent}, because a high-entropy node below an edge the
walk rarely takes adds little to it.

The \emph{AUC of the reach-a-leaf curve} is the shape of the walk. Let $F(h)$
be the probability that a descent has reached a leaf by depth $h$, with
$h_{\max}$ the maximum depth, and let $r$ be the distribution of the leaf a
descent ends at. Then
\begin{equation}
  \mathrm{AUC} = \frac{1}{h_{\max}}\int_0^{h_{\max}} F(h)\,\mathrm{d}h,
  \qquad
  \text{effective leaves} = 2^{\entropy(r)},
  \label{eq:auc}
\end{equation}
where $F$ is linearly interpolated between integer depths, so the integral is
the trapezoid rule over unit steps. $F$ is the cumulative distribution of the
stopping depth, and AUC measures how early walks terminate. In the example
$60\%$ of walks stop at depth~1, at proof of work or proof of authority, and
the rest at depth~2, so $F = (0, 0.6, 1.0)$ over $h_{\max} = 2$ and
$\mathrm{AUC} = \tfrac{1}{2}\big(\tfrac{0 + 0.6}{2} + \tfrac{0.6 + 1.0}{2}\big)
= 0.55$. It is one when every root is a leaf, since then $F(0) = 1$, and
approaches zero for a single chain, where nothing stops before the bottom: a
chain of five nodes has $F = (0, 0, 0, 0, 1)$ and an AUC of $0.5 / 4 =
0.125$. Between the two, a high value marks a shallow, wide DAG and a low
value deep branches. Two DAGs can resolve the same bits, one in a few wide
steps and one in many narrow ones, and AUC separates them; we report the
expected stopping depth beside it, $1.4$ in the example.

\emph{Effective leaves} is the destination of the walk. It is $2^{\entropy(r)}$,
the perplexity of $r$: if descents end at each of $n$ leaves equally often,
$\entropy(r) = \log_2 n$ and the measure equals $n$, and when heavy edges
funnel the walk into a few leaves it falls toward that few whatever the leaf
count. It therefore counts the leaves the hierarchy delivers as distinct
outcomes, not the leaves it draws. The example has four leaves, reached with
probabilities $0.50$, $0.36$, $0.10$ and $0.04$, so $\entropy(r) = 1.55$ bits
and the DAG has $2^{1.55} = 2.9$ effective leaves: liquid staking is reached
by one walk in twenty-five and barely functions as a destination. Four leaves
reached equally would give $4$; four of which one takes $97\%$ of the walks
would give about $1.2$. On a tree $\entropy(r)$ equals the expected bits per
descent, as it does here, since the bits resolved along a path identify its
end; in a DAG with shared children the two differ, which is why both are
reported.

Together the three expose three failures of a hierarchy: low bits per
descent, branches that do not discriminate; AUC near one, a structure so flat
that it adds little over a list; effective leaves far below the leaf count, a
DAG wide on paper that a few branches dominate. We compute all three overall,
per category, and for the sub-DAG obtained at every display threshold from 0
to 1, where hiding an edge turns its child into a root, which is the
sensitivity study of \cref{sec:exp:rq2}. On the example, hiding the edges
below $0.2$ detaches proof of authority and liquid staking into roots of their
own: two of the three roots are then leaves, the remaining branch resolves
$0.99$ bits, bits per descent fall from $1.55$ to $0.33$, and AUC rises to
$0.84$ because two walks in three end at depth~0. That is the pattern the
sweep reports on the real DAG.

\textbf{Label space.} Tagging places an item on node $y$ and, by is-a, on every
ancestor. Let $I$ be the items of the batch, $V(y)$ the values of term type
$y$, and $T$ the accepted tags, each a triple $(i, y, v)$ with $i \in I$,
$y \in \mathcal{Y}$ and $v \in V(y)$ placing item $i$ at $y$ with value $v$.
For node $y$ let
\begin{equation}
  \label{eq:closure}
  S(y) = \{\, i \in I : (i, y, v) \in T \text{ for some } v \,\}, \qquad
  C(y) = S(y) \cup \bigcup_{x \in \mathrm{ch}(y)} C(x),
\end{equation}
where $S(y)$ is the set of items tagged directly at $y$ and $C(y)$ is its
\emph{closure}, the items on $y$ or on any descendant, so that
$C(y) = \bigcup_{x \preceq y} S(x)$ over all $x$ with an is-a path to $y$,
$x$ itself included; a leaf has $C(y) = S(y)$. The recursion is well defined
because $G$ is acyclic, and the closures of two children may overlap, since an
item may be tagged at both or a node may have two parents. The
\emph{residual} of $y$ is the part of its closure that stops there,
\begin{equation}
  \label{eq:residual}
  R(y) = C(y) \setminus \bigcup_{x \in \mathrm{ch}(y)} C(x) \;\subseteq\; S(y),
\end{equation}
the items placed on $y$ but on none of its children; for a leaf,
$R(y) = S(y)$. An item tagged at a child and also at $y$ belongs to $S(y)$
and $C(y)$ but not to $R(y)$.

We illustrate the sets and the four statistics that follow on the example of
\cref{fig:toylabel}: a node $y$, consensus mechanism, with one child,
finality, and four tagged items. The values of $y$ are alternative answers
to its question, which mechanism validates a transaction; the child asks a
different question, whether settlement is deterministic, that an item about
consensus may go on to answer. The two never overlap in meaning: a child is
a further question, not a sub-answer. Item a answers both questions, b and
d answer only the parent's, and c answers only the child's. The direct set
$S(y) = \{a, b, d\}$ holds the items tagged at $y$; item c enters the
closure $C(y) = \{a, b, c, d\}$ only through the child, since a tag at
finality implies consensus mechanism by is-a; and the residual
$R(y) = \{b, d\}$ drops item a, which the child also covers. From these
sets we compute four statistics per node: two describe the node's own
split into values and use the direct tags only, since these alone carry a
value of $y$; two describe how the node's items divide among its children
and use the closure.

\subsubsection{Value entropy}
For $v \in V(y)$ let
\begin{equation}
  \label{eq:valcount}
  n_v(y) = |\{\, i \in I : (i, y, v) \in T \,\}|, \qquad
  p_y(v) = \frac{n_v(y)}{\sum_{v' \in V(y)} n_{v'}(y)},
\end{equation}
where $n_v(y)$ is the number of items carrying value $v$ at $y$: the braces
collect every item $i$ of the batch $I$ for which the tag set $T$ holds a
triple $(i, y, v)$, item $i$ tagged at term type $y$ with value $v$, and the
bars $|\cdot|$ count them. The second quantity, $p_y(v)$, divides that count
by the total count over every value of $y$, the dummy index $v'$ running over
$V(y)$ in the denominator, so that $p_y$ is a probability distribution over
the values of $y$ summing to one: the share of the node's answers that fall
on $v$. An item tagged at $y$ with two values counts once under each, so
$\sum_v n_v(y) \ge |S(y)|$, with equality when no item carries two values
at $y$. The \emph{value entropy} is
$\entropy(p_y) = -\sum_{v} p_y(v) \log_2 p_y(v)$, the impurity of the node's
own split: $\log_2 |V(y)|$ when the values are used equally and near zero
when one value absorbs everything. It is undefined when $S(y) = \emptyset$.
In the example item c never answered the consensus question and is ignored.
The counts are $n_{\mathrm{PoS}} = 2$, $n_{\mathrm{PoW}} = 1$ and
$n_{\mathrm{PoA}} = 0$, summing to $3 = |S(y)|$ because no item carried two
consensus values; had item d also been tagged PoA, the sum would be 4 while
$|S(y)|$ stayed 3. The value distribution is $p_y = (2/3, 1/3, 0)$, so
\begin{equation*}
  \entropy(p_y) = -\tfrac{2}{3}\log_2\tfrac{2}{3} - \tfrac{1}{3}\log_2\tfrac{1}{3} = 0.92 \text{ bits},
\end{equation*}
against a ceiling of $\log_2 3 = 1.58$ if the three values were used
equally and a floor of 0 if every item said PoS. At 0.92 bits the node's
question still separates items on this content, though not as well as it
could.

\subsubsection{Dominance}
The \emph{dominance} is $\max_v p_y(v)$, the share of the most frequent
value, the same information as the value entropy in a blunter form that is
easier to threshold: a node whose dominance is high has a question with, on
this content, effectively one answer. Like the entropy it is undefined when
$S(y) = \emptyset$. In the example the dominance is $2/3 = 0.67$, below the
collapse threshold of 0.85 used by the proposals below. Nine items in ten
saying PoS would give dominance 0.9 and, with $|S(y)| \ge 10$, the node
would be reported as collapsed.

\subsubsection{Residual fraction}
The \emph{residual fraction} is $|R(y)|/|C(y)|$, the share of the node's
items that stop at it rather than continuing to a child. It is zero when
every item on $y$ is also on some child, so the children cover the node
completely, and one when the node has no children or none of them is used.
In the example the closure is used, so item c now counts, and the residual
fraction is $|R(y)|/|C(y)| = 2/4 = 0.5$: half the items that belong to
consensus mechanism go no further than the node itself, since b and d state
which mechanism is used but say nothing the child asks. A large residual
with many items is the signal that a child dimension may be missing. With a
real batch, enough such items would make $y$ a discovery target, and Task~E
would be shown b and d and asked what question about consensus the catalogue
does not yet pose.

\subsubsection{Branching gain}
The \emph{branching gain} is the entropy of the empirical split of $C(y)$
over the children and the residual,
\begin{equation}
  \label{eq:gain}
  g(y) = \entropy(\hat q_y), \qquad
  \hat q_y(x) = \frac{|C(x)|}{Z_y},\qquad
  \hat q_y(\mathrm{stop}) = \frac{|R(y)|}{Z_y},
\end{equation}
for $x \in \mathrm{ch}(y)$, with $Z_y = |R(y)| + \sum_{x \in \mathrm{ch}(y)}
|C(x)|$. Here $\hat q_y$ is a probability distribution over the options
open to a walk sitting at $y$: step to child $x$, with mass the size of
that child's closure, or stop, with mass the size of the residual; $Z_y$
is the sum of those masses, so that the options sum to one. The hat
distinguishes $\hat q_y$ from $q_y$ of \cref{eq:branch}, which used the
model's edge weights where $\hat q_y$ uses item counts, and \cref{eq:gain}
is \cref{eq:branch} with that substitution and a stop option added. The
normaliser $Z_y$ is needed because the closures of two children may
overlap, so $|R(y)| + \sum_x |C(x)|$ can exceed $|C(y)|$; when they are
disjoint, $Z_y = |C(y)|$ and $\hat q_y$ is simply the share of each child's
closure and of the residual in the node's closure. A node without children
has $\hat q_y(\mathrm{stop}) = 1$ and $g(y) = 0$. In the example the walk
arriving at $y$ either steps to finality, with mass $|C(\mathrm{fin})| =
2$, or stops, with mass $|R(y)| = 2$, so $Z_y = 4 = |C(y)|$,
$\hat q_y = (1/2, 1/2)$ and
\begin{equation*}
  g(y) = \entropy(\tfrac{1}{2}, \tfrac{1}{2}) = 1 \text{ bit}:
\end{equation*}
the step from $y$ resolves one full bit of uncertainty about where an item
ends up. The normaliser matters once closures overlap: with a second child,
reward mechanism, and item a tagged there too, the masses would be finality
2, reward 1 and stop 2, summing to $Z_y = 5$ against $|C(y)| = 4$, and
dividing by $|C(y)|$ would give shares summing to $1.25$; dividing by $Z_y$
gives $\hat q_y = (0.4, 0.2, 0.4)$. The child itself has no children, so
$\hat q_{\mathrm{fin}}(\mathrm{stop}) = 1$ and $g(\mathrm{fin}) = 0$.

A random descent now starts at a root with probability proportional to its
closure and at $y$ stops with $\hat q_y(\mathrm{stop})$ or moves to child
$x$ with $\hat q_y(x)$; a node without children stops with probability one.
From the descent we compute, as for the prior walk above, the expected
bits resolved, the AUC of the reach-a-leaf curve, the expected depth, and
the effective leaves $2^{\entropy(r)}$ for the distribution $r$ of the node
a descent stops at, all from content rather than from the prior weights. The
prior values of \cref{eq:branch,eq:auc} are recomputed for the version in
force and reported beside them.

Read together, the four statistics of the example say the following.
Entropy 0.92 and dominance 0.67 say the node's question still separates
items; a residual fraction of 0.5 says half of them have nowhere to go
beneath it; a gain of 1 bit says the one existing child is taken about as
often as not. The node is healthy on its own values and under-served by
children, the profile of a discovery target rather than of a collapsed or
dormant one.

\textbf{Deterministic proposals.} From the statistics the loop names, without
a model call, the \emph{dormant} nodes ($C(y) = \emptyset$), the
\emph{collapsed} nodes (dominance $\ge 0.85$ with $|S(y)| \ge 10$), the nodes
of highest branching gain, and the \emph{discovery targets}, nodes with
$|R(y)| \ge 5$ and $|R(y)|/|C(y)| \ge 0.3$: enough items stop at $y$ to ask
whether a dimension below it is missing. Dormant and collapsed nodes are
reported, not removed. On technical content the legal branches are dormant by
nature of the batch, and removing a node is a decision across batches that
the loop does not take.

\textbf{Discovery (Task E).} One call per target, without the corpus, at
effort \texttt{medium}. The model sees the node's identifier, name, question,
category, values and child term types; the seeds the tagger proposed at that
node, marked as possibly wrong; and up to 40 residual items, those with the
most confident tag at $y$ first, each as its identifier, title, the evidence
spans of its tags at $y$ and its first sixty words, with the total residual
count stated. It proposes at most four candidates, most useful first: a new
value of $y$, when the residual items exhibit a category of the node's
question that its value list lacks, or a new child term type with a question
and two to six values, when they can be split by a question the catalogue
does not ask; each with the identifiers of the residual items that support it
and one evidence span of at most twenty words, and an empty list when the
residual is the natural end of the branch. A candidate is accepted when three
tests hold. \emph{Support}: at least five of the identifiers it lists are
residual items of $y$ among those shown. \emph{Gain}: because the shown items
are a sample of the residual, the support $m$ among the $n_s$ shown is
extrapolated to the whole residual, $\hat m = \mathrm{round}(m\,|R(y)|/n_s)$
when $n_s < |R(y)|$ and $\hat m = m$ otherwise, capped at $|R(y)|$, and the
candidate must raise the branching gain at $y$ by at least 0.1 bit when it
becomes a child that captures $\hat m$ items out of the residual,
\begin{equation}
  \label{eq:cgain}
  \Delta(y, \hat m) = \entropy(\hat q_y^{+}) - \entropy(\hat q_y) \ge 0.1,
\end{equation}
where $\hat q_y^{+}$ replaces the stop option of \cref{eq:gain} by two options
of mass $\hat m/|C(y)|$ and $(|R(y)| - \hat m)/|C(y)|$, renormalised. A value
candidate is scored the same way, as the split its items would make. Without
the extrapolation a node with thousands of residual items could accept
nothing, since support is capped by the forty items shown. \emph{Evidence}:
the span is found verbatim, by the matcher of \cref{sec:method:verify}, in one
of the supporting items. The thresholds 5, 0.3, 0.1 and 40 are parameters of
the loop and were the same in every iteration.

\textbf{Evolution.} One call at effort \texttt{high} consolidates the accepted
candidates of an iteration into version $t{+}1$. It sees every existing node
as identifier, category, name and question, grouped by category, and every
accepted candidate with its kind, target node, label, question, definition,
values, gain and supporting items, and must merge candidates that ask the same
question at different nodes, taking the union of their values (two to eight)
and items; place each new term type under the existing node or nodes it
refines, under the category root when it applies across the category, and
under two parents only when it refines both; keep a candidate value unless it
duplicates an existing one; and invent nothing the candidates do not support.
The answer is validated: a new term type needs a unique identifier, parents
that exist, at least two values and a valid category, or it is skipped; a new
value is skipped when the term type already has it under another case.
Additions carry the candidate status, the iteration, the labels merged into
them and their supporting items, and a new edge carries weight one until the
is-a query of \cref{sec:method:hierarchy} re-estimates it against the corpus.
When nothing was accepted no version is written. Every iteration appends to a
log its sample, items, tags and verified evidence, the objectives from tags
and from the prior, the dormant, collapsed and target counts, the candidates
and the accepted ones, what was added and the resulting node, edge and value
counts, and the tokens, cost at list price, API seconds, wall time and
parallelism of its three stages.

\subsection{Retrieval over the DAG}
\label{sec:method:retrieval}

Part~3 turns the tagged content into an index on $G$ and answers queries with
set algebra on the DAG instead of text search.

\textbf{Index.} The index places the tagged items of every batch on the
current version of $G$. Items are read batch by batch and numbered
$0..N{-}1$ in that order. An item is skipped when the tagger marked it
off-topic, when none of its tags names a node of that version, or when an
earlier batch already holds it. Evolution only adds nodes and never renames
one, so a tag made on an earlier version still names a node of the current
one, and a node added in version $t$ holds only items tagged on version $t$
or later, since an item is tagged once. In this section $I$ is the set of
indexed items and $N = |I|$, so $S$, $C$ and $R$ of
\cref{eq:closure,eq:residual} are taken over all batches rather than one.

\textbf{Postings.} Every set of items the index stores is a \emph{bitset},
an $N$-bit integer whose bit $i$ is one exactly when item $i$ is in the set.
Union, intersection and difference of two sets are then the bitwise OR, AND
and AND with the complement of two integers, and the size of a set is the
number of its one bits. Each operation is one pass over two $N$-bit
integers, a machine word at a time, in place of a merge of two lists of item
identifiers, so its cost is small but still linear in $N$. Node $y$ stores
three kinds of posting: its direct items $S(y)$; for each value $v \in V(y)$,
the items that carry $v$ at $y$,
\begin{equation}
  \label{eq:pair}
  S(y, v) = \{\, i \in I : (i, y, v) \in T \,\},
\end{equation}
so that $n_v(y) = |S(y, v)|$ in \cref{eq:valcount}; and its closure $C(y)$,
stored once rather than recomputed by each query. Each of the five
categories of term type (asset, technology, actor, activity, obligation or
risk) stores the items with a direct tag on one of its nodes. On the example
of \cref{fig:toylabel}, number the items a, b, c, d as 0 to 3 and write a
bitset as four bits with item d first. Then $S(y) = 1011$ sets the bits of
a, b and d. The values split it into $S(y, \text{PoS}) = 1001$ and
$S(y, \text{PoW}) = 0010$, and $S(y, \text{PoA})$ is empty. Finality, a
leaf, has $S(\mathrm{fin}) = C(\mathrm{fin}) = 0101$. The closure
$C(y) = S(y) \cup C(\mathrm{fin}) = 1111$ is one OR. The residual of
\cref{eq:residual} is $C(y) \setminus C(\mathrm{fin}) = 1010$, items b and d,
and $C(y) \setminus S(y) = 0100$ is item c, which reaches $y$ only through
its child.

\textbf{Item records.} Beside its bit in the postings, each item keeps a
record of its tags and a pointer to its text. For each node $x$ it is
tagged at, the record holds $\kappa(x)$, the highest confidence among the
item's tags at $x$, and the first evidence span the tagger gave there; for
each pair $(x, v)$ it holds the confidence of that tag. The text itself is
not copied into the index. It stays in the batch file the tagger read, one
JSON record per item and line, and the pointer is the file together with the
\emph{byte offset} at which the item's line begins, counted from the start of
the file when the index is built. Displaying an item seeks to that offset and
parses one line, at the same cost wherever the line sits in the file.
Matching, scoring and facets use only the postings and the records, so text
is read for the results shown and for no others.

\textbf{Structure of $G$.} The index also precomputes, from $G$ alone, the
structure that queries and their expansion use. Nodes are numbered as well,
and a set of nodes is a bitset over them. With $\mathrm{pa}(y)$ the parents
of $y$, one pass in reverse topological order, children before parents,
gives the descendants of every node, and one pass in topological order gives
its ancestors,
\begin{equation}
  \label{eq:descanc}
  \mathrm{desc}(y) = \{y\} \cup \bigcup_{x \in \mathrm{ch}(y)} \mathrm{desc}(x),
  \qquad
  \mathrm{anc}(y) = \{y\} \cup \bigcup_{p \in \mathrm{pa}(y)} \mathrm{anc}(p).
\end{equation}
Each set is the OR of sets computed earlier in the pass, so a pass reads
every edge once. The descendant sets build the closure postings,
$C(y) = \bigcup_{x \in \mathrm{desc}(y)} S(x)$, the bitset form of
\cref{eq:closure}; whether $z$ is an ancestor of $x$ is one bit of
$\mathrm{anc}(x)$; and the common ancestors of a set of nodes are the AND of
their ancestor sets. A subtree query reads the stored posting $C(y)$ and
does not walk $\mathrm{desc}(y)$, so the node bitsets add nothing to its
cost.

The closure follows every is-a edge, whatever its weight. How strongly a
descendant $x$ is a kind of $y$ is its \emph{path strength},
\begin{equation}
  \label{eq:rho}
  \rho(x, y) = \max_{x = z_0 \to z_1 \to \cdots \to z_m = y} \;
  \prod_{j=1}^{m} w(z_{j-1} \to z_j), \qquad \rho(x, x) = 1,
\end{equation}
the best product of the edge weights of \cref{sec:method:hierarchy} over the
is-a paths from $x$ up to $y$, with $\rho(x, y) = 0$ when $y$ is not an
ancestor of $x$; an edge added by evolution counts with weight one until it
is re-estimated. A search upward from each node, keeping the best product
found so far for each ancestor, computes $\rho$ for all pairs. On the DAG of
\cref{fig:toydag}, $\rho(\text{delegated PoS}, \text{consensus mechanism}) =
0.9 \times 0.4 = 0.36$ and $\rho(\text{liquid staking}, \text{consensus
mechanism}) = 0.1 \times 0.4 = 0.04$, yet the closure of consensus mechanism
holds the items of liquid staking as fully as those of proof of work. A light
edge thus brings all of a child's items into its parent, which near the
roots of the real DAG makes closures cover most of the collection
(\cref{sec:exp:rq4}). The queries below use $\rho$ to restrict a subtree to
strong descendants and to rank the items reached through weak ones lower.

The \emph{lowest common ancestors} of a set of nodes are its common
ancestors that are not a proper ancestor of another common ancestor. A set
can have several, since a node can have several parents. Delegated PoS and
liquid staking have the common ancestors proof of stake and consensus
mechanism, and only proof of stake is lowest. The \emph{information content}
of a node,
\begin{equation}
  \label{eq:ic}
  \mathrm{IC}(y) = -\log_2 \frac{|C(y)|}{N},
\end{equation}
takes $|C(y)|$ as the number of one bits of the closure, counting an empty
closure as one half so that the value stays finite. A node is more
informative the fewer items its subtree holds. In \cref{fig:toylabel}, with
$N = 4$, consensus mechanism holds every item and has $\mathrm{IC}(y) = 0$,
and finality holds two and has $\mathrm{IC}(\mathrm{fin}) = 1$ bit. The
\emph{similarity} of two nodes,
\begin{equation}
  \label{eq:sim}
  \mathrm{sim}(x, x') = \max_{z \in \mathrm{anc}(x) \cap \mathrm{anc}(x')}
  \rho(x, z)\, \rho(x', z), \qquad \mathrm{sim}(x, x) = 1,
\end{equation}
says how strongly both are kinds of one thing. Because $\mathrm{anc}(x)$
contains $x$, a node and its ancestor are at least as similar as the path
strength between them. The measure follows the edge weights, not the depth
of the shared ancestor. In \cref{fig:toydag}, delegated PoS and proof of
work have similarity $0.36 \times 0.5 = 0.18$ through consensus mechanism,
more than delegated PoS and its sibling liquid staking, $0.9 \times 0.1 =
0.09$ through proof of stake, because liquid staking is only weakly a kind
of proof of stake. On version~\RCat\ the index builds in \RBuildSec\
seconds, so it is rebuilt after each iteration, offsets included, rather
than updated in place.

\textbf{Queries.} A query is a boolean expression over five kinds of atom,
listed in \cref{fig:toyquery} with their results on a small example. For a
node $y$, the atom \texttt{y} denotes the subtree $C(y)$ and \texttt{y!} the
direct items $S(y)$. The atom \texttt{y=v} denotes $S(y, v)$ of
\cref{eq:pair}. Its value is given either as a code $v_j$, the $j$th value of
$y$, or as a label, matched first ignoring case and then as the only label of
$y$ that contains it; a value that matches neither way is rejected with the
list of values of $y$. The atom \texttt{y\textasciitilde}$\sigma$ denotes the
subtree restricted to strong descendants,
\begin{equation}
  \label{eq:strongsub}
  C_\sigma(y) = \bigcup \{\, S(x) : x \in \mathrm{desc}(y),\ \rho(x, y) \ge \sigma \,\},
\end{equation}
which contains $S(y)$ because $\rho(y, y) = 1$. The atom \texttt{@c} denotes
the items with a tag on a node of category $c$. Atoms combine with AND, OR,
NOT and parentheses, and a space between two operands is AND. NOT binds
tightest, then AND, then OR, so \texttt{x y OR z} reads
\texttt{(x AND y) OR z}. Evaluation walks the parse tree over bitsets, with
AND and OR as intersection and union and NOT as the complement within $I$.
Four kinds of atom are one lookup of a stored posting. The
strength-restricted atom enumerates $\mathrm{desc}(y)$, tests $\rho(x, y)$
for each descendant and unites the direct postings that pass, so it is the
only atom whose cost grows with the subtree. It is also the atom that keeps a
general node selective, since $C(y)$ follows every edge whatever its weight.
At $\sigma = 0.3$ it cuts the mean result of a subtree query on the real
index from \RClosureHits\ to \RStrengthHits\ items (\cref{sec:exp:rq4}). On
the example, \texttt{PoS} returns $i_2$, $i_3$ and $i_5$,
\texttt{PoS NOT DPoS} returns $i_3$ and $i_5$, and \texttt{PoS DPoS OR PoW}
returns $i_2$ and $i_4$.

\textbf{Ranking.} A score orders the matches. Write $\kappa_i(x)$ for the
$\kappa(x)$ of item $i$'s record, zero when $i$ has no tag at $x$, and
$\mathcal{A}^{+}$ for the atoms of the query that are not negated. The score
of item $i$ is the sum of its match strengths,
\begin{equation}
  \label{eq:score}
  \mathrm{score}(i) = \sum_{a \in \mathcal{A}^{+}} m(i, a).
\end{equation}
For a subtree atom on $y$ the strength is
$m(i, a) = \max_{x \in \mathcal{Y}} \kappa_i(x)\, \rho(x, y)$, the best
product of tag confidence and path strength over the nodes the item is
tagged at; a tag outside the subtree contributes nothing, since
$\rho(x, y) = 0$ there. For \texttt{y!} the strength is $\kappa_i(y)$, for
\texttt{y=v} the confidence of the tag $(i, y, v)$, and for \texttt{@c} the
highest $\kappa_i(x)$ over the nodes $x$ of category $c$. A
strength-restricted atom takes the subtree strength over all the item's
tagged nodes, so its threshold decides whether an item matches but not which
tag scores it. The node $x$ that attains the maximum is reported with the
item, ties are broken by item identifier, and the $k$ best are returned. For
the query \texttt{CM} every item of the example matches, with the scores of
\cref{fig:toyquery}. Item $i_1$, tagged at consensus mechanism itself, ranks
first. Item $i_2$, two levels down, outranks $i_3$ at proof of stake because
its tag is more confident, and $i_5$, reached through the light edge to
liquid staking, ranks last. Because strengths add, an item that matches both
operands of an OR ranks above one that matches only one, and a negated atom
filters the result without adding to any score.

\textbf{Generalisation and expansion.} When the atoms of $\mathcal{A}^{+}$
name two or more distinct nodes, the result carries their lowest common
ancestors as a broader query, which the engine offers but does not run. For
\texttt{DPoS OR LS} it offers proof of stake. When fewer than $k$ items
match, the engine relaxes the query to nearby nodes. For each node named in
$\mathcal{A}^{+}$ it takes the six nodes most similar to it by
\cref{eq:sim}, pools them, and adds their subtrees in decreasing similarity
until at least $k$ items are held. An item first reached through node $z$,
similar to query node $y$, scores $\mathrm{sim}(y, z)$ times its subtree
strength at $z$, is marked as expanded with $z$ and the similarity, and is
listed after every match. On the example with $k = 3$, \texttt{LS} matches
only $i_5$. The nodes most similar to liquid staking are proof of stake at
0.10, delegated PoS at 0.09 and consensus mechanism at 0.04. The subtree of
proof of stake adds $i_2$ and $i_3$, scored $0.10 \times 0.81 = 0.081$ and
$0.10 \times 0.80 = 0.080$, and the expansion stops. The expansion ignores
the boolean structure of the query. An expanded item comes from a node
similar to one query node and need not satisfy the other atoms, the ANDs or
the NOTs.

\textbf{More like this.} An item is also a vector over the nodes, with
component
\begin{equation}
  \label{eq:itemvec}
  u_i(y) = \max_{x \in \mathcal{Y}} \kappa_i(x)\, \rho(x, y)\, \mathrm{IC}(y)
\end{equation}
at node $y$. Every ancestor of a tagged node carries weight, discounted by
the path strength from the tag and by how general the ancestor is. A root
whose subtree holds every item has $\mathrm{IC} = 0$ and contributes
nothing. Given item $i$, ``more like this'' ranks by the cosine of $u_i$ and
$u_j$ the items $j$ that share at least one tagged node with $i$, and
reports the shared nodes. An item tagged only at a parent or a sibling of
$i$'s nodes is not a candidate, however close its vector.

\textbf{Free text.} A request in words becomes a query in one of two ways.
The lexical route treats each node and each value of the catalogue as a
short document, made of a node's name, question, description and aliases or
of a value's label and definition. Each distinct word of the request with
three or more characters adds its inverse document frequency
$\log(M / \mathrm{df}(w))$ to every document that contains it, with $M$
documents of which $\mathrm{df}(w)$ contain $w$. The three best documents
become atoms, \texttt{y} for a node and \texttt{y=v} for a value, joined by
OR. The join favours recall, and one atom can contain another. For ``rug
pull scam on a decentralised exchange'' the atoms are the subtree of
\ttype{exchange\_venue\_type}, its own value ``decentralised exchange
(DEX)'', which that subtree already contains, and the value ``fraud / scam
(investment or romance)'' of \ttype{risk\_type\_illicit\_finance}; the words
rug and pull occur in no catalogue entry. The model route makes one call to
Haiku~5.5 at effort \texttt{low} with thinking disabled. The call carries the
catalogue block of Task~C as a cached system block and an instruction that
offers subtree atoms, value atoms and the boolean operators, but not the
direct, strength-restricted or category atoms, and asks for the query string
alone. The string is parsed and run like a typed query, and one that names
an unknown node or value is rejected. Neither route sees the result of the
query it writes. Neither is evaluated in this paper, since the judged queries
of \cref{sec:exp:rq3} and the workloads of \cref{sec:exp:rq4} are written in
the query language directly.

\textbf{Facets.} For a result set of $n$ items and a node $y$ it touches, the
query nodes or, for a category query, the roots of that category, two kinds
of question could be asked next: the child subtrees of $y$, where each child $x$ with items is an option of size $n_x = |C(x) \cap \text{result}|$ and the
items on no child form a residual option, and the values of $y$, where each
value with items is an option and the items not tagged at $y$ form the
residual. Picking option $o$ with probability proportional to its size $n_o$,
the expected narrowing is
\begin{equation}
  \label{eq:facet}
  \mathcal{N}(y) = \sum_{o} \frac{n_o}{\sum_{o'} n_{o'}} \log_2 \frac{n}{n_o},
\end{equation}
zero for an option that covers the whole set. With disjoint options,
\cref{eq:facet} is the information gain of the question when every item is
its own class, the criterion Basu Roy et al.~\cite{roy2008minimum} consider
for choosing facets over a database. Options may overlap, as an item can sit
in two child subtrees. The normalisation by the total option size, which
FACeTOR~\cite{kashyap2010facetor} also uses for its entropy, keeps the
weights a distribution, but they are then no longer the probabilities of the
answers a user gives. The engine returns the six facets of highest
$\mathcal{N}$ with their options and sizes, and the one at the top is the
next question. On the result set $C(y)$ with the child subtrees and the
residual as options, $\mathcal{N}(y) = g(y) - \log_2 (Z_y / |C(y)|)$, so
\cref{eq:facet} equals the branching gain of \cref{eq:gain} when no item lies
in two child subtrees and falls below it otherwise: the objective that grows
the DAG also routes a search through it. The navigation experiment of
\cref{sec:exp:rq4} uses this directly, offering at each step the facets of
every node the remaining items carry tags on and taking the option that
contains the target.
