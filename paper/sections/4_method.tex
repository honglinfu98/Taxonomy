\section{The \sys Framework}
\label{sec:method}

\sys consists of three modules (\cref{fig:overview}): (1) definitions-first
corpus construction (\cref{sec:method:corpus}); (2) cache-grounded extraction,
which fixes what the model is asked and how the corpus is served
(\cref{sec:method:task,sec:method:run}); and (3) citation verification
(\cref{sec:method:verify}). A fourth stage orders the resulting term types into
a hierarchy (\cref{sec:method:hierarchy}).

\subsection{Definitions-First Corpus Construction}
\label{sec:method:corpus}

We do not give the model whole statutes. A regulation such as \src{MiCA}
defines its vocabulary in a few articles and spends the rest of its length on
obligations that refer back to those definitions. The classification criteria
we are after live in the definitions articles, the glossaries, the
classification conditions and the descriptions of business models, so we take
those sections and nothing else. \Cref{tab:corpus} lists the result: 21 legal
instruments from the EU, the UK, the US and six international bodies, plus two
academic taxonomies of blockchains~\cite{tasca2019taxonomy} and of
crypto-assets~\cite{zhang2026cryptotaxonomy} and one paper describing a
domain corpus~\cite{hernandez2026dltcorpus}, with reference lists and large
tables removed.

Each PDF is converted with \texttt{pdftotext} and cut by line ranges or by
regular-expression markers that we specify once per document. The US bills
need the layout-preserving mode because their two-column line numbering
scrambles the plain output, and we drop page footers such as the bill number
that would otherwise leak into every section. The Senate-reported print of the
\src{CLARITY Act} reproduces the House-passed text before the Senate
substitute, so we take Title~I once, from the House file, and only the
substitute's definitions and its section on network tokens from the Senate
file. The corpus is one XML-tagged text file in which every document carries an
integer index and metadata and is split into \texttt{<section label="...">}
blocks, so a citation can name a document and a section unambiguously. The file
holds 32 sections and 97.8 thousand words, which the model's tokeniser counts
as 235,298 tokens.

\subsection{The Extraction Task}
\label{sec:method:task}

    "citations"}], "citations", "sources", "notes"}], "coverage_notes"}

\Cref{fig:prompt} shows the prompt. The system instructions define the objects
of \cref{sec:problem} in the model's terms and state the grounding and quality
rules; they precede the corpus and never change, so the cache survives every
task. The user prompt states the scope, which covers assets, DLT systems,
actors, activities, and obligations or risks when the sources themselves use
them as criteria, gives the JSON schema, and asks for ordering by category and
then by the number of grounding documents. The model is told that the corpus is
its only source of truth and that outside knowledge may be used to recognise
what the corpus says, never to add to it.

\textbf{Manifest.} Our first run cited section labels from memory and got
them wrong in 9\% of citations, with 65 term types. We therefore append a
\emph{manifest}: one line per document listing its index, title and every
exact section label, with the instruction that no other labels exist. The
manifest is generated from the corpus at run time, so it cannot drift from the
file the model sees.

\subsection{One Call over a Cached Corpus}
\label{sec:method:run}

We place the whole corpus in the system prompt, after the stable instructions
and behind a prompt-cache breakpoint with a one-hour lifetime; the task prompt
is the user message. Every later task, and every prompt iteration, then pays
only for the small uncached part. The choice is also methodological. Quality
rule four asks the model to recognise that \src{MiCA}'s ``referencing the value
of one official currency'' and the \src{GENIUS Act}'s ``fixed amount of monetary
value'' answer the same question. A retriever would have to anticipate that two
passages that share few words define the same dimension; a model that sees all
24 documents at once does not. The cost of a run is therefore linear in the
corpus size, with the corpus priced at the cache-read rate and only the task
prompt and the output priced in full; we report measurements in
\cref{sec:exp:cost}.

A single streamed call produces the output. We disable the model's adaptive
thinking because on a first attempt it spent more than 100,000 thinking tokens
on this corpus without emitting any text, whereas without thinking it answers
directly. We parse the JSON and, if a response is cut off by the output limit,
salvage every complete term type and flag the result as truncated.

\subsection{Citation Verification}
\label{sec:method:verify}

A quote that the model labels verbatim may still be invented, compressed, or
attached to the wrong section, so we check all of them. For each citation we
look up the document and section, normalise both the quote and the section text
to lower-case alphanumerics, and accept the quote if it is a substring. If it is
not, we split the quote into 12-character shingles and accept it when at least
80\% of them occur inside one window of the section twice the quote's length.
Localising the matches tolerates footnote markers, hyphenation and the spacing
artefacts of PDF extraction, and rejects a paraphrase stitched from phrases
that occur in different places. When a quote fails under the cited label but
passes under another label of the same document, we \emph{relabel} it,
correcting the section, keeping the model's label alongside, and counting the
citation as verified. Everything else is rejected and listed in a report
(pseudo-code in \cref{app:verify}). Every citation in the published output
carries a \texttt{verified} flag, and the rejection rate is our measure of
desideratum~(D1). Verification establishes that the quote exists where the
model says it does; it does not establish that the quote supports the
dimension, a limit we return to in \cref{sec:exp:rq1}.
