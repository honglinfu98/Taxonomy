A taxonomy is a hierarchy of classes that organises a domain's vocabulary so
that machines and people can classify, browse and retrieve its objects
consistently. On the Web, taxonomies drive product catalogues, search
verticals and content moderation, and the community has studied how to expand
and complete them from Web text for years~\cite{shen2020taxoexpan,
wang2021hef,jiang2022taxoenrich,arous2023taxocomplete,shi2024icon}. Crypto-assets
are a domain in which the vocabulary itself is contested. Tokens are issued,
traded and described on the Web, and the documents that say what a token
\emph{is} are themselves Web publications: MiCA in the EU, the GENIUS and CLARITY Acts in the US, the UK's
cryptoasset regulations, the guidance of FATF, the Basel Committee, the FSB
and IOSCO, and academic taxonomies~\cite{tasca2019taxonomy,zhang2026cryptotaxonomy}.

\paragraph{Relevance to the Web.}
This work falls under the Semantics and Knowledge track. The research challenge
is Web-specific because the definitions that govern crypto-assets are
published, versioned and consumed as Web documents by heterogeneous bodies,
no shared vocabulary links them, and the assets they describe exist only as records on
Web-accessible ledgers. The result is a provenance-tracked vocabulary that
explorers, exchanges and compliance services can use to classify tokens across
jurisdictions and regenerate when an instrument changes.


These sources disagree in a specific way. \Cref{fig:one} shows the term
\term{stablecoin}. \src{MiCA} splits it into e-money tokens, which reference one
official currency, and asset-referenced tokens, which reference anything else.
The \src{GENIUS Act} and the UK regulations admit only a fiat currency as the
reference. The Basel Committee admits a commodity and treats algorithmic
stabilisation as a different category. No text names ``what the asset references'' as a
dimension, yet each uses it to draw a legal or prudential boundary. We call such a dimension a \emph{term type}, a
question along which definitions discriminate, together with the set of values
the sources admit. The reference asset is one of many; issuer identifiability,
fungibility and consensus mechanism are others, recurring across instruments
under different names.

Existing approaches do not recover term types from such a corpus. First,
manually built taxonomies of crypto-assets and of blockchain
architectures~\cite{tasca2019taxonomy,zhang2026cryptotaxonomy} encode one
perspective each and cannot be regenerated when an instrument changes. Second, LLM methods for taxonomy
completion~\cite{shi2024icon}, hierarchical
classification~\cite{zhang2025teleclass} and tagging~\cite{wan2024tntllm,
li2023taggpt} start from a label space that already exists, and ontology
learning with LLMs~\cite{babaeigiglou2023llms4ol} is evaluated on general-domain
benchmarks where the gold hierarchy is known. Third, none of them ties an induced class to the passage that licenses it,
which decides whether a compliance team can audit the result.

In this paper we propose \sys, a framework that induces term types from the
definitions in a corpus of legal instruments and academic taxonomies and
attaches provenance to every node. \sys builds a definitions-first corpus, in
which each document is reduced to the sections that define or classify; it
extracts term types in one pass over the whole corpus held in a cached context,
so that the model can recognise the same dimension under different names across
sources; it requires a document index, an exact section label and a verbatim
quote for every term type and every value; and it verifies each quote against
the corpus, repairing wrong section labels and rejecting quotes it cannot find.
It then orders the catalogue. For each term type it asks for a cited probability
distribution over the more general term types it specialises, and consolidates
the weighted edges greedily into a directed acyclic graph (DAG), so that a term
type can sit under more than one parent. Every element of the resulting ontology cites its source. The ontology is then
put to work as a label space: Web content is tagged onto its nodes with evidence spans, the tags
measure how much each branch discriminates and where items stop short of any
child, and a discovery step proposes new values and dimensions at those nodes,
accepting only candidates that raise the information gain and are supported by
verified evidence. The seed built from law is never modified; what the content
adds is marked as such. Finally the tagged content is indexed on the graph as bitsets,
queried by set algebra weighted by is-a path strength, and navigated by the
facet with the highest expected narrowing.

\smallskip\noindent\textbf{Contributions.}
\begin{itemize}
  \item We formalise term type induction, in which a corpus of definitional
    text yields the classification dimensions it uses, with values and
    provenance, without a seed taxonomy or gold labels (\cref{sec:problem}).
  \item We propose \sys, which combines a definitions-first corpus, single-pass
    extraction over a cached whole-corpus context with mandatory citations, a
    citation verifier, a per-node is-a query consolidated into a DAG, and a
    maintenance loop that tags content onto the DAG and grows it by measured
    information gain, and a bitset index that retrieves and navigates the
    tagged content by the same gain (\cref{sec:method}).
  \item We release \corpus, a definitions-first corpus of 24 documents across
    four jurisdictions, and the resulting ontology of 93 term types with 317
    values, 480 citations and 279 weighted is-a edges
    (\cref{sec:exp:rq1,sec:exp:rq2}).
  \item We evaluate on \corpus and DLT-Corpus (\cref{sec:exp}): 97.9\% of
    citations verify, 69 term types record a cross-source conflict, the
    hierarchy resolves \BBits\ bits per descent, \NIterWord\ maintenance
    iterations over the whole on-topic DLT-Corpus of \AllItems\ items verify
    \EvidMin--\EvidMax\% of tag evidence and add \AllAddedTypes\ dimensions, and the index answers queries over \RItems\
    items \RSpeedMin\ to \RSpeedMax\ times faster than a flat scan. On a 300-item gold set the DAG index reaches NDCG@10 \RetSonNDCG\ on
    Sonnet tags against \RetSonFlatNDCG\ for the same tags without closure
    and \RetBMNDCG\ for BM25, while the catalogue prompt leaves tagging
    micro-F$_1$ level with a flat label list (\cref{sec:exp:rq3}). Against
    zero-shot, chunked RAG, RAPTOR and TnT-LLM pipelines over the same corpus
    and model, our catalogue scores highest downstream, type micro-F$_1$
    0.34 against 0.12--0.24 (\cref{sec:exp:rq5}); ablations show that the
    citation requirement, not the prompt's quality rules, makes the model read
    the corpus, 39 term types without it against 93 (\cref{sec:exp:rq6}). On
    378 Web token descriptions labelled by a market-data site without our
    catalogue, the ontology's tags as learned features match 8,334 TF-IDF
    features on micro-F$_1$ and beat them by 15 points on macro-F$_1$, while
    the catalogue as prompt context adds nothing (\cref{sec:exp:rq7}). Code and data are at an anonymised
    repository.\footnote{\url{https://anonymous.4open.science/r/Taxonomy-77BF/}}
\end{itemize}
