\section{Experiments}
\label{sec:exp}

We answer seven research questions.
\textbf{RQ1}: How many dimensions does the corpus support, how widely are
they shared, and how faithful are the citations?
\textbf{RQ2}: What hierarchy do the term types form and how grounded are its
edges?
\textbf{RQ3}: Does the DAG serve as a label space for Web content, and does
the content reveal where it must grow?
\textbf{RQ4}: Does the DAG index beat a flat tag table on latency, and does
facet gain navigate to a target?
\textbf{RQ5}: How does the catalogue compare with expert taxonomies and with
other ways of building one from the same corpus with the same model?
\textbf{RQ6}: How much do the manifest, the citation requirement, the
definitions block, the effort setting and the model matter?
\textbf{RQ7}: Does the ontology improve an independent classification of Web
token descriptions whose labels were made without it?

\subsection{Experimental Setup}
\label{sec:exp:setup}

\textbf{Datasets.} \corpus is described in \cref{tab:corpus}. No benchmark
exists for term type induction, so \corpus is both the input and, via its
citations, the ground truth for faithfulness. For RQ3 the
content is DLT-Corpus~\cite{hernandez2026dltcorpus}, 37,440 scientific papers
and 49,023 USPTO patents, of which we keep English items whose title or
abstract names a DLT term (40\% of papers, 49\% of patents) and draw disjoint
batches: a pilot of 150 papers and 150 patents, then a tenth of each
collection (3,744 papers, 4,902 patents) per iteration until the on-topic
pool of \AllItems\ items is exhausted; an item is the title and abstract
capped at 450 words. For RQ4 the index holds the tagged
items of all \RIterWord\ batches on version \RCat. A held-out gold set of \GItems\ items (150 papers, 150
patents) is excluded from the supervised baseline's training. DLT-Corpus items may occur in the model's pretraining data, which we
cannot rule out; the gold labels are produced with the catalogue in view, so
contamination would help every system alike. For RQ7 the items are 378
descriptions of the 500 largest coins by market capitalisation on CoinGecko,
collected on 28 October 2026, each at least 40 words and capped at 400, with
the site's own categories as labels: after excluding 215 category names that
are not properties of the asset (ecosystem membership, index constituents,
portfolios, listings), the 28 categories carried by at least ten items are
kept, 351 items have at least one and the mean is 2.26 per item. The site
assigned these labels without our catalogue in view, so the task does not
favour our label space.

\textbf{Baselines.} For tagging, the same model given a flat list of term
types and value labels without questions, definitions or hierarchy, and a
supervised TF-IDF with one-vs-rest logistic regression trained on the
production tags outside the gold set; both LLM taggers are also run with
\texttt{claude-sonnet-5-5}. For retrieval, Boolean match on the
flat tags, the supervised labels through our index, and BM25 over title and
text with the query rendered as the term type's name, question and values.
For term type induction (RQ5), four alternative Task~A pipelines over the
same corpus, model and output schema, so that the same verifier, Task~B and
tagger apply to every catalogue: \emph{zero-shot}, which sees the task, the
schema and the 24 document titles but no text; \emph{chunked RAG}, which
splits the sections into 129 passages of at most 900 words, retrieves the
BM25 top~8 for each of 40 model-written queries, runs the Task~A instructions
with the citation rule over each retrieved set, and consolidates the
per-query proposals in one call; \emph{RAPTOR}~\cite{sarthi2024raptor}, the
same with a three-level summary tree added to the retrieval pool, where a
summary may inform a term type but cannot be quoted; and
\emph{TnT-LLM}~\cite{wan2024tntllm}, which summarises every passage and
builds the taxonomy bottom-up over batches of 30 summaries with a final
review pass. As an expert key we extract, with verified quotes, the 39
dimensions that the two taxonomy papers in the corpus propose. For RQ6,
Task~A is rerun with one ingredient changed and everything else as in the
main run: the manifest removed, the citation requirement removed, the
definitions of term, term type and grounded removed, effort set to
\texttt{low}; and, for the model, a second Haiku run with the same prompt and
two \texttt{claude-sonnet-5-5} runs at effort \texttt{medium} and \texttt{high}.
For RQ7, six systems. Without the ontology, the model sees the description
and the category list. With the ontology as context, it also sees the
cached catalogue block and must state the catalogue values the description
instantiates before choosing categories. With the ontology as the only
evidence, the unchanged tagger tags the description and a second call sees
those tags with their definitions, never the description. Three supervised
classifiers, one-vs-rest logistic regression on 1--2-gram TF-IDF (8,334
features), on 432 binary indicators of the tagger's (term type, value)
pairs, term types and implied ancestors, and on both.

\textbf{Metrics.} For faithfulness, the share of citations whose quote the
verifier finds in the cited document (exact or relabelled) and the rejection
rate; smaller is better. For coverage, the number of term types, values, aliases, grounding documents
per term type and recorded conflicts. For the hierarchy we report the structural counts and the objectives of
\cref{sec:method:hierarchy}; for retrieval, latency against a flat scan with
identical results and the steps and bits a navigation needs to reach $k$
items. For tagging against the gold set, micro- and macro-F$_1$ over
(term type, value) labels and over term types; for retrieval on the gold
items, P@10, R@10, NDCG@10 and MAP with relevance graded from the gold
labels. For RQ5, agreement with our catalogue as F$_1$ over term types
paired by an LLM judge that sees both catalogues and keeps a pair only when
it is found in both directions; coverage of the expert key by the same judge;
the structure metrics of Task~B; and type-level micro- and macro-F$_1$ of the
tagger on the gold items when given each catalogue, with a baseline's types
mapped onto the gold space by the judge. For RQ6, the same size, verification,
judged agreement and expert coverage, with the agreement split into recall of
the main run's term types and precision of the variant's, and the share of citations whose section label needed no relabelling. For
RQ7, micro- and macro-F$_1$, precision and recall over the 28 site
categories; a predicted name outside the list is dropped.

\textbf{Implementation.} Tasks A and B use \texttt{claude-haiku-5-5} at
effort \texttt{high} with thinking disabled, the corpus behind a one-hour
prompt cache.
Task~A is one streamed call with a 120,000-token output limit; Task~B is 93
calls with six entries each, four in parallel; Task~C runs at effort \texttt{medium}
with 6 to 24 items in flight; gold annotation uses \texttt{claude-opus-5-5}
at effort \texttt{high}. All runs are API calls from a laptop; no GPU is
involved. The retrieval engine is pure Python over integer bitsets and is
timed on one core of the same laptop. Gold-set systems
are run \EvalRunsWord\ times, LLMs by sampling and the classifier by seed,
and reported as mean $\pm$ sd; Task~A repeats are compared in \cref{sec:exp:rq1}.
The RQ5 baselines, the RQ6 variants and their judge use
\texttt{claude-haiku-5-5}; a baseline catalogue goes through the unchanged
Task~B and tagger. RQ6 variants are run once each. The RQ7 LLM systems use
\texttt{claude-haiku-5-5} and are run three times; its supervised
classifiers use five-fold cross-validation repeated over three shuffles with
balanced class weights, with tag features from the first tagging run.

\textbf{What the corpus supports.} The run produced 93 term types with 317
values and 212 aliases (\cref{tab:taska}). We make the
following observations. (1) Technology dimensions are the largest group,
because the blockchain taxonomy of Tasca and Tessone contributes architectural
dimensions that no legal instrument uses. (2) Asset and actor dimensions are the most
widely shared: an asset term type is grounded in 4.5 documents on average,
and service-provider status in 13 of the 24. (3) Twenty term types rest on a single document, mostly distinctions the
academic taxonomies draw and the law does not yet make. Every document is
cited by at least one term type, the 2021 FATF guidance most, by 27.


Sixty-nine term types carry a note recording a disagreement between sources.
The reference-asset dimension of \cref{fig:one} is returned with five
values, seven grounding documents across four jurisdictions, and a note
recording the jurisdictional split (full record in the artefact).


\textbf{Faithfulness.} Of the 480 citations, 463 matched the cited section
verbatim under normalisation, 7 were relabelled, and 10 were rejected, a
rejection rate of 2.1\% (\cref{tab:taska}, last column), from 95.1\% for actor
dimensions to 100\% for asset and activity dimensions. One cited label did not exist, a subsection heading inside
the FinCEN guidance, and six named a wrong section of the right document; the
verifier located the quote in all seven. \Cref{tab:errors} in \cref{app:results} lists the ten rejections with a
diagnosis. Two
quotes share no five-word sequence with the cited section. Three compress a
definition, two drop the enumerated items of a statutory list, as in
``'blockchain' means any technology (i) where data is shared across a
network'', and three reproduce most of a sentence and then rephrase its end.
They point at the right passage but are not verbatim, so we keep them as
unverified. Every term type keeps at
least one verified citation, but five values were supported only by a rejected
quote and are therefore unverified.

Verification checks existence, not relevance: whether the 470 verified
citations support their term types is left to the expert validation deferred
to the next version (\cref{sec:conclusion}). The run is one call of 302
seconds with 85,729 output tokens and 235,298 cached input tokens,
\$\BillTaskA\ at list price.

\textbf{Stability.} A second Haiku run with the same prompt returned
\AgHTypes\ term types, \AgHMatched\ of which match one of the first run's 93
by name, question or alias (F$_1$ \AgHF, value Jaccard \AgHJaccard), with
\AgHVerifiedPct\% of its \AgHCites\ citations verified; a
\texttt{claude-sonnet-5-5} run, cut off at the output limit, returned
\AgSTypes\ with \AgSMatched\ matched (F$_1$ \AgSF) and \AgSVerifiedPct\% of
\AgSCites\ verified. Grounding holds across runs and models; the set of
dimensions does not. \Cref{sec:exp:rq6} rescores these runs with an LLM judge
beside the prompt ablations.

\label{sec:exp:rq2}

  E[depth] its expected length; AUC the area under the reach-a-leaf curve (1 when
  every root is a leaf); Eff.\,lv.\ is the effective number of leaves
  $2^{\entropy(r)}$ for the leaf-reach distribution $r$. Single run.}

  \scriptsize
  \input{tables/task_b_summary}

\textbf{Structure.} The 93 calls returned \BWeighted\ weighted candidate edges,
of which consolidation kept \BEdges\ and dropped \BDropped\ for closing a cycle,
with \BTies\ exact tie (\cref{tab:taskb}). We make the following observations.
(1) Every category closes under a single root, the crypto-asset definitional
criteria for assets, the governance model for technologies, service-provider
status for actors, the service type for activities, and AML applicability for
obligations; the model was free to return \emph{none} for any node and did so
with median mass 0.13. (2) The DAG is deep and multi-parented: a node keeps
\BMeanParents\ parents on average and up to \BMaxParents, the technology category
reaches depth 14, and a random descent resolves \BBits\ bits before ending at
one of \BEffLeaves\ effective leaves. (3) In the asset category the reference-asset dimension
specialises the legal classification and carries the stablecoin class,
redemption mechanism and tokenisation form beneath it, but second-choice
parents carry nearly as much mass: \emph{legal classification} and
\emph{stablecoin regulatory class} both received 0.32 as parents of
\emph{reference asset}, and \BMutual\ node pairs were each proposed as the
other's parent. The weights are coarse, with a
median top weight of \BMedianTop, so we read them as rankings rather than
calibrated probabilities. The \BCalls\ calls took \BSeconds\ seconds and read
\BCacheTokens\ million cached tokens, \$\BillTaskB\ at list price; every
stage's recorded usage is in \cref{tab:billing} (\cref{app:results}),
\$\BillTotal\ in all.


\textbf{Sensitivity to the threshold.} \Cref{fig:spectrum} (\cref{app:results}) sweeps a display
threshold over the consolidated DAG. Hiding edges below 0.2 halves the edges
and the bits per descent; at 0.4 a third of the nodes are roots and a descent
resolves half a bit; above 0.6 the graph is a forest of singletons.

\textbf{Faithfulness of edges.} The entries carry \BCites\ citations, of which
\BVerified\ (\BVerifiedPct\%) verify, \BRelabelled\ after relabelling, and
\BRejected\ are rejected, a higher rejection rate than in Task~A. Only
\BEntriesCited\ of the \BWeighted\ entries cite anything, allowed for
low-probability entries, and \BTopNoCite\ top entries cite nothing, which is
not. Rejected quotes are mostly short phrases from long sections, such as
``Wrapped tokens''.

\textbf{Tagging.} \Cref{tab:evolution} summarises the \NIterWord\ iterations:
a pilot of \CItems\ items on the seed, then batches of \TItems\ items on
versions 1 to \LCat, the last being the \LItems-item remainder of the pool,
so the whole on-topic collection, \AllItems\ items with \AllTags\ tags, is
tagged. \EvidMin--\EvidMax\% of the evidence spans are found verbatim in the
item. We make three observations. (1) The content exercises the technical
half of the DAG: in iteration 2, \TCovTech\ items carry a technology tag
against \TCovActor\ an actor tag and \TCovOblig\ an obligation tag; the legal
nodes need regulatory content. (2) Dimensions discovered in one iteration are among the
most used in the next: ledger purpose, added in iteration 1, was tagged on
\TLedgerPurpose\ items in iteration 2 with a value entropy of
\TEntLedgerPurpose\ bits, and every dimension added in iterations 2 and 3
received items in the next. (3) Tagging cost \$\LCostPerItem\ per item; all \NIterWord\ iterations took
\$\AllCost\ and \AllWallMin\ minutes at up to \WorkersMax\ parallel requests.

\textbf{Measurement.} Measured from the tags, a content-driven descent
resolves \BitsSeq\ bits over the \NIterWord\ iterations against \EBitsPrior\
to \LPriorBits\ from the prior weights: the gain rises from the
seed as discovered nodes absorb residual mass and then settles near seven
bits. Collapsed nodes, \CollapsedSeq\ per iteration, are led by the DLT data
structure with 96\% of its items on ``blockchain'' and are also the largest
residual pools, where discovery is pointed; dormant nodes fall from
\MDormantFirst\ on the pilot batch to none by iteration 4.

\textbf{Discovery and evolution.} The iterations found \TargetsSeq\ targets
and accepted \AcceptedSeq\ of \CandidatesSeq\ candidates, producing version
\VLastNum\ with \VLastNodes\ term types, \VLastEdges\ edges and \VLastValues\
values (\cref{tab:accepted}, \cref{app:results}). The additions are
dimensions a legal corpus would not contain, such as the cryptographic family
behind a privacy guarantee, and later iterations refine earlier ones, as when
iteration 3 placed a zero-knowledge proof system variant under that family. Two failures are visible. Consolidation does
not always merge candidates that ask the same question: iteration 1 kept two
application-domain dimensions under different smart-contract nodes, and
iteration 4 added a cross-chain interoperability mechanism beside the
cross-chain transfer mechanism of iteration 2. And with raw support counts, capped by the forty items shown, only
10 of 76 candidates cleared the gain test against residual pools of thousands
in iteration 2, which is why support is extrapolated to the residual (21 of
81 accepted).

\textbf{Gold-set evaluation.} Verified evidence shows that a span exists,
not that the tag is right. On \GItems\ held-out items with \GLabels\
LLM-adjudicated labels over \GTypes\ term types (\cref{tab:evaltag,tab:evalret},
\cref{app:results}), the Haiku tagger with the catalogue reaches label
micro-F$_1$ \DagMicro, level with the same model given a flat label list
(\FlatMicro) and with the supervised classifier (\SupMicro), whose macro-F$_1$
collapses to \SupMacro; with Sonnet 5.5 both prompts rise together, \SonMicro\
with the catalogue and \SonFlatMicro\ with the flat list. The catalogue
prompt therefore does not raise tagging accuracy; the model does, and the
catalogue trades recall for precision. The DAG index does raise retrieval:
over \NQueries\ judged queries it reaches NDCG@10 \RetSonNDCG\ on Sonnet tags
against \RetSonFlatNDCG\ for the same tags matched without closure (node
queries \RetSonNode\ against \RetSonFlatNode), \RetDagNDCG\ against
\RetFlatNDCG\ on Haiku tags, and \RetBMNDCG\ for BM25, at \RetDagLat\ against
\RetBMLat\ microseconds per query; two-atom AND queries remain the weak case
(\RetSonAnd).

\textbf{Index.} The on-topic, tagged items of all \RIterWord\ batches,
\RItems\ with \RTags\ tags, are placed on version \RCat, where \RNodesTagged\
of \RNodes\ nodes and \RPairs\ node--value pairs hold items; the index builds in \RBuildSec\

\RFlatMinMs\ to \RFlatMaxMs\ milliseconds for the scan, \RSpeedMin\ to
\RSpeedMax\ times faster, with \RMismatches\ mismatches in \RQueries\ results.
(2) Navigation by facet gain works. For \RTargets\ random target items we
take, from the whole collection, the option of the offered facet that contains
the target until at most $k{=}\RK$ items remain or 15 steps are spent (ideal

\subsection{RQ5: Against Expert Taxonomies and LLM Baselines}
\label{sec:exp:rq5}

\Cref{tab:rq5} compares the catalogues. We make four observations. (1) The
corpus is most of the catalogue. Without it the same model and prompt return
32 dimensions, a fifth of ours by the judge, and the actor, activity and
obligation branches that only the legal instruments define are nearly
absent. Zero-shot is also the one uncontaminated expert-coverage number:
0.26 of the key, against 0.67 for ours. (2) Retrieval fragments the
catalogue. Chunked RAG proposes 498 term types over its 40 queries and keeps
81 after consolidation, with 750 values, 2.4 times ours per type, padded with
near-duplicates drawn from different passages; its citations verify because
each is cut from a retrieved passage, but only 39 of its types map to a gold
dimension. RAPTOR's summaries lose verbatim text, 87\% of citations verified
against 98--99\% for the passage-based catalogues, and do not recover
coverage. (3) Bottom-up generation over-generates. TnT-LLM accumulates 170
term types from 129 summaries and its review pass removes none; it has the
highest raw expert coverage at the lowest precision (0.18), cannot cite, and
scores lowest downstream because 37 of its 170 types map to a gold dimension.
(4) Our second run agrees with the first at F$_1$ 0.60 by the judge, against
0.51 by the lexical matcher of \cref{sec:exp:rq1}: 51 of its 76 types ask a
question the first run asked. Structure after Task~B separates the catalogues
little, 3.6 to 5.9 bits per descent; the Task~A stage does.

\textbf{Expert key.} Our catalogue contains 26 of the 39 dimensions. The 13
it misses are mostly engineering sub-dimensions of Tasca and
Tessone~\cite{tasca2019taxonomy}, such as network topology, block storage,
fee structure and coding language, which the task prompt, asking for
dimensions a source uses as a legal, prudential or technical boundary, does
not request; adding them is a scope choice rather than a defect of the
method.

\textbf{Limits.} The downstream score favours our catalogue: the gold labels
were adjudicated in the space of catalogue version \EvalCat, and a baseline is
scored through the judge's mapping onto it, so the column measures how far
each catalogue reproduces our dimensions on real items rather than an
independent task. Expert coverage is contaminated for every corpus-based row,
and the judge is the generators' model. The RAG and RAPTOR variants use BM25
and TF-IDF clustering rather than dense retrieval, the cheapest faithful
versions. RQ5 cost \$8.83, of which \$5.8 is Task~B over the four baseline
catalogues.

\subsection{RQ6: What Each Ingredient Contributes}
\label{sec:exp:rq6}

\Cref{tab:rq6} removes or changes one ingredient of Task~A at a time. We make
four observations. (1) The citation requirement is what makes the model read
the corpus. Without it the same model, prompt and corpus return 39 term
types in 111 seconds, with recall 0.36 of the main run's types at the
highest precision (0.85) and under half the expert key. The quality rules
alone do not force a section-by-section pass; having to quote does. Dropping
citations does not add ungrounded dimensions, it shortens the catalogue.
(2) The manifest fixes labels, not dimensions. Without it 21\% of citations
name a section label that the verifier had to relabel (57 of 271) and six
more are rejected, against 1.5\% relabelled with it, worse than the 9\% of
the uncontrolled first run that motivated the manifest
(\cref{sec:method:task}); the catalogue itself, 62 term types at judged
agreement 0.65, sits inside the run-to-run band. (3) The definitions block
controls granularity. Without the definitions of term, term type and grounded
the model returns 111 term types with the highest recall of the main run
(0.68) and the lowest precision (0.57): more splitting and more topic-like
dimensions, at 0.29 precision against the expert key. (4) Effort and model
trade size for precision. Effort low gives 46 term types; Sonnet 5.5 gives
54 at effort medium and 72 at effort high before hitting the output ceiling,
at ten times the cost; all three verify every citation and exceed the Haiku
repeat in precision against the main run. The dimension set is
model-dependent, with judged agreement 0.52 to 0.57 against 0.60 for a Haiku
repeat; the grounding is not.

\textbf{Limits.} Every variant's judged agreement with the main run, 0.50 to
0.65, lies at or below the run-to-run level of 0.60, so one run per variant
shows effects on size, label accuracy and precision and not on the identity
of the dimensions; a second run per variant would give the spread. The judge
and the expert key carry the caveats of RQ5. RQ6 cost \$1.55, of which
\$1.48 is the four Task~A calls.

\subsection{RQ7: An Independent Downstream Task}
\label{sec:exp:rq7}

\Cref{tab:rq7} reports the only task in the paper whose labels were made
without our catalogue. We make three observations. (1) As prompt context the
ontology does not help. Description plus catalogue equals description alone,
micro-F$_1$ 0.570 against 0.571 and macro-F$_1$ 0.557 against 0.563, at five
times the cost; this repeats the gold-set result of \cref{sec:exp:rq3}: the
model, not the catalogue in its prompt, sets the accuracy of an LLM
classifier. (2) The ontology tags carry the category information. A model
that sees only the tagger's output and never the description keeps 94\% of
the description-only micro-F$_1$ (0.535). As learned features, 432 binary tag
indicators match 8,334 TF-IDF features on micro-F$_1$ (0.478 against 0.487)
and beat them by 15 points on macro-F$_1$ (0.402 against 0.257): the word
classifier learns the frequent categories only, while a tag such as
\emph{references a single official currency} is the same feature for every
stablecoin whatever words its page uses, so the tag classifier reaches the
rare ones. Words plus tags is the best learned classifier, 0.514 and 0.423.
(3) The LLM systems over-predict. All three return 3.4 to 4.0 categories per
coin against 2.26 in the gold, so recall is 0.67 to 0.79 and precision 0.44
to 0.46; the site's assignment is sparser than the descriptions support,

\textbf{Failure case.} Stacks is a Bitcoin layer~2, labelled Infrastructure,
Layer~2 and Smart Contract Platform. The description alone gets all three.
With the catalogue the model first claims a base-chain value of the DLT
architecture dimension and then answers Layer~1, because catalogue version
\EvalCat\ has no term type whose question asks whether a system is a base
chain or a second layer; the nearest is a candidate value two levels down,
\emph{layered main and sub-chains}, which the model did not use. Classifying
through the catalogue forced a base-chain reading. The same mechanism helps
KuCoin, where the actor dimensions lead the catalogue prompt to the gold
Exchange-based Tokens that the description-only prompt misses. Fourteen coins
are right only without the catalogue and eighteen only with it.

Framework, Meme, DePIN), which caps every system; the supervised tag features come from one tagging run; the supervised classifiers are not tuned. RQ7 cost \$1.73.
